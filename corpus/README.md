# corpus/

Teaching material for **Experiment B** (the corpus-extension run). Everything here is
generated by `../build_extension_corpus.py` — nothing is copied from a third party, so
there is no licensing question about publishing derived results.

Regenerate with:

    python build_extension_corpus.py

## What is here and why

| File | Eval category targeted | Lines |
|---|---|---|
| `negation_and_correction.md` | `negation` (lang_31–33) | 191 |
| `spatial_relations.md` | `spatial_relations` (lang_40–42) | 106 |
| `categories_and_kinds.md` | `categories_and_analogies` (lang_46–48) | 134 |

Five further eval categories — grammar, opposites, reference, sequence and everyday
knowledge — are **deliberately left untaught** so they act as a control group.

## Eval separation

The generator drops any line that reproduces a test item, and re-shuffles until the
whole assembled file is clean as well, because `reject_eval_leakage` matches against
whole-file text and two individually safe lines can spell out a prompt when adjacent.
One line was dropped on that basis: it reproduced `lang_32` exactly.

This is a normalized contiguous-prompt check, not a semantic one. These public tests
guided what I chose to teach, which makes this a **development benchmark** — a claim
about unseen generalization would need tests that never influenced the corpus.

## A formatting detail that matters

Multi-clause examples write the period **without a following space** (`blue.it`).
`chunk_text` splits passages at sentence boundaries, so `"a . b"` would become two
separate passages and the negation and spatial patterns could never be learned inside a
single training example. Omitting the space keeps one passage and produces identical
tokens.
